# Stories Studio

Из текста поста собирает **колоду Instagram-Stories** в одном самодостаточном HTML-файле (`stories.html`) с локальным Python-сервером. Опционально перед этим собирает **мудборд** — 60–90 картинок из интернета по темам поста — и вставляет лучшие сразу в карточки.

Всё нужное лежит внутри скилла: движок редактора, правила раскладки, снипеты слайдов, шаг поиска картинок. Внешних зависимостей нет, кроме Python 3 и браузера.

Пусть `$SKILL` — папка этого скилла. Ассеты — в `$SKILL/assets`, референсы — в `$SKILL/references`.

---

## ⛔ ПРАВИЛО НОЛЬ — ТЕКСТ АВТОРА: ЧТО МОЖНО МЕНЯТЬ

Stories — это **раскладка** текста по слайдам. Мысль, порядок и голос автора сохраняются.

- **Обычный режим** (пользователь не сказал «слово в слово»): внутри абзаца можно убрать несущественный нюанс или дубль, чтобы высказывание стало точнее и акцентнее. Абзацы целиком не удаляются, смысл не меняется. Если на слайде стоят крупные цифры 1, 2, 3, слова «во-первых / во-вторых» убираются.
- **Режим «слово в слово»** (пользователь так и сказал): меняются только опечатки.
- **Опечатки** исправляются всегда и без вопросов.

| Можно (обычный режим) | Нельзя (ни в каком режиме) |
|---|---|
| Разбить длинный абзац на 2–3 слайда по синтаксической границе | Удалить абзац целиком |
| Убрать внутри абзаца дубль или несущественный нюанс | Поменять смысл, добавить свои слова |
| Обернуть слово в `<b>` / `<i>` / выделение для акцента | Перефразировать, заменять слова синонимами |
| Исправить опечатку | Менять порядок предложений и абзацев |

**Проверка перед сдачей:** `scripts/verify_text.py` сверяет текст слайдов с исходником. В режиме «слово в слово» — посимвольно. В обычном режиме сокращённую версию положи рядом (`source-slides.md`) и сверяй слайды с ней, а пользователю перечисли все правки двумя списками: опечатки и сокращения (было → стало).

Полные правила — в **[references/composition-rules.md](references/composition-rules.md)**.

## Порядок работы

### 1. Получить текст и определить папку

- Текст в запросе → берём как есть. Путь к `.md`/`.txt` → читаем. Ничего нет → просим.
- Сохранить исходник дословно в `<папка>/source.md` — с ним потом сверяется текст.
- Папка колоды: `./<slug>-stories/` (или папка поста, если работаем внутри неё). `slug` — 1–3 слова из заголовка.

### 2. (Опционально) Мудборд — поиск картинок

Если пользователь просит карточки **с картинками / мудбордом** — сначала собрать мудборд. Если нет — пропустить этот шаг и шаг 3, слайды поедут на сером плейсхолдере.

- Извлечь из поста 3–5 визуальных тем (люди, места, произведения-референсы, настроения).
- Запустить **2–4 параллельных поисковых субагента** (модель `sonnet`) — по теме на агента. Шаблон промпта, рабочие источники и правила приёмки — в **[references/image-search.md](references/image-search.md)**.
- Цель: **60–90 картинок**, только прямые URL картинок, выборочно проверенные `curl -sI`.
- Для абстрактных понятий — отдельный мозговой штурм метафор с людьми и известными фигурами; внешность людей в кадрах-типажах — под контекст и читателя (см. `image-search.md`).
- Вместе с картинками искать **видео под тему** — интервью героев, рекламу, эпизоды из фильмов, самые яркие и точные, даже если в посте их нет: 3–6 кандидатов с таймкодами темой «Видео-кандидаты» и в `videos.md`. Скачивать и резать только после одобрения пользователя (`image-search.md`, «Видео-кандидаты»).

### 3. (Опционально) Файл данных и страница мудборда

Собрать всё в `<папка>/moodboard-data.js`:

```js
window.MOODBOARD_DATA = [{ src, label, source, orient, section }, ...];
```

Один файл питает и страницу мудборда, и попап-галерею в редакторе. Проверить: `node --check moodboard-data.js`.

Страница мудборда (по желанию): скопировать `$SKILL/assets/moodboard-template.html` → `<папка>/moodboard.html`, заменить `{{TITLE}}`, `{{TITLE_HTML}}`, `{{SUBTITLE}}`.

### 4. Развернуть редактор

```bash
SKILL="<путь до этого скилла>"
DST="<папка колоды>"

mkdir -p "$DST/images"
cp "$SKILL/assets/template.html"    "$DST/stories.html"
cp "$SKILL/assets/server.py"        "$DST/server.py"
cp "$SKILL/assets/placeholder.svg"  "$DST/images/placeholder.svg"
cp -R "$SKILL/assets/backgrounds"   "$DST/backgrounds"   # галерея фонов в панели «Слайд» (по желанию)
```

Свои фоны: `python3 "$DST/backgrounds/add_backgrounds.py" <папка с картинками> [--group "Название"]` — картинки ужимаются и появляются в галерее панели «Слайд». Колоду, собранную прошлой версией редактора, переносят в свежий движок: `python3 "$SKILL/scripts/upgrade_deck.py" старый.html новый.html` (слайды и правки сохраняются, старый файл не меняется).

Тег `<script src="moodboard-data.js">` уже в шаблоне — если файл есть рядом, кнопка «Мудборд» появится сама; если нет, она просто скрыта. Так же с `backgrounds/backgrounds.js`: нет папки — нет галереи фонов.

⚠️ Внутри инлайн-скрипта шаблона нельзя писать закрывающий тег `script` даже в комментарии или строке — браузер оборвёт скрипт, и редактор перестанет работать.

### 5. Разложить слайды

Читать **[references/composition-rules.md](references/composition-rules.md)** (правила ритма) и **[references/slide-templates.md](references/slide-templates.md)** (готовые снипеты — брать оттуда, не писать руками).

- Удалить 4 демо-слайда внутри `<div class="viewport">`, вставить реальные.
- Слайд 1 — TITLE. Обложка решает, нажмут ли на пост, — сделай **2–4 варианта обложки** (разный хук, картинка, плашки) и предложи на выбор.
- После плотного по тексту слайда следующий — легче (меньше текста, больше картинки). Не влезает крупным кеглем — делить слайд, а не уменьшать шрифт.
- Дальше: ~60–70 % BODY, 1–2 QUOTE, BULLETS для перечислений, 1 CLOSING.
- Фоны: белый/серый чередовать, 1–2 чёрных на пост, максимум 1 акцентный цвет.
- `story-label` (`N / TOTAL`) и `data-slide` — по порядку. Над каждым слайдом — комментарий `<!-- IMG: какая картинка нужна -->`.
- Если мудборд собран — сразу вставить лучшую по смыслу картинку в каждый слайд прямым `<img src="https://...">` (шаблон сам прогонит внешний URL через прокси при экспорте). Иначе — плейсхолдер.
- Футер каждого слайда оставить **пустым**: `<span class="footer-sig"></span>`. Подпись пользователь задаёт сам (см. ниже).

### 6. Подпись в футере

Футер не зашит. При **первом открытии** `stories.html` в браузере редактор показывает окошко и спрашивает адрес блога или имя для угла карточек. Если пользователь выбрал «Без подписи» — угол остаётся пустым и больше не спрашивается. Поменять — кнопкой «Подпись» в тулбаре. Значение хранится в `localStorage`, поэтому в HTML его прописывать не нужно.

### 7. Запустить сервер

```bash
cd "$DST" && python3 server.py 8089 &
open http://localhost:8089/stories.html
# если собирали мудборд:
open http://localhost:8089/moodboard.html
```

Всегда `server.py`, а не `http.server`: его эндпоинт `/proxy?url=…` нужен, чтобы html2canvas мог экспортировать внешние картинки без CORS-ошибки, а `/save` принимает `Cmd+S` — редактор записывает вёрстку обратно в `stories.html` (прежняя версия уходит в `stories.backup.html`).

### 8. Проверка перед сдачей

1. **Текст:** `python3 $SKILL/scripts/verify_text.py "$DST/stories.html" "$DST/source.md"` — все расхождения должны быть либо пробельными артефактами разметки, либо исправленными опечатками из твоего списка.
2. Футеры пустые (`footer-sig`), фоны чередуются, `story-label` соответствует слайдам.

### 9. Передать пользователю

Кратко: таблица слайдов (№ / паттерн / фон / содержание / картинка), варианты обложки, **список исправленных опечаток и сокращений**, видео-кандидаты с вопросом, какие брать, ссылка(и) и памятка редактора:

- клик по тексту или картинке → справа открывается панель свойств; когда ничего не выбрано — панель слайда (фон цветом, пипеткой, картинкой из галереи или файлом)
- текст: размер S/M/L, кегль ±, интервал строк, шрифт, выравнивание, цвет, выделения и плашки (9 стилей; у слова одно выделение — новое заменяет старое, без выделения стиль и цвет меняют все выделения блока), слой; ширина тянется за левый/правый край
- картинка: масштаб, поворот (ползунок или кружки у углов, Shift — шаг 15°), обрезка, форма (как есть / скругление / круг), растяжка в фон с любой стороны, слой, замена файлом, URL, перетаскиванием или из мудборда
- блоки двигаются мышью в любую сторону за ручку ⠿; ⌫ удаляет выбранный блок; ⌘Z / ⇧⌘Z — отмена и повтор
- тулбар: «+ Текст», «+ Картинка», «Дубль», фон, формат 9:16 / 4:5 / 16:9, «Поля», «Мудборд», «Подпись», «PNG» открытого слайда, меню «Экспорт» (JPEG, все слайды), «Сохранить» (`Cmd+S` — вёрстка пишется обратно в файл)

## Сколько слайдов по длине текста

| Длина текста | Слайдов |
|---|---|
| 100–200 слов | 6–8 |
| 200–400 слов | 9–13 |
| 400–700 слов | 13–18 |
| 700+ слов | делить на 2 колоды — спросить пользователя |
