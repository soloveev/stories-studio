# Поиск картинок для мудборда (субагентами)

Проверенный процесс: 3 параллельных поисковых субагента по темам собирают 60+ прямых URL за один заход; добор вторым заходом доводит до 80–90.

## Дизайн запуска

- **2–4 субагента параллельно**, по одному на тему (или паре смежных тем). Запускать одним сообщением, `model: "sonnet"` — поисковая задача, Opus не нужен.
- Целевой объём: **15–25 картинок на тему**, суммарно **60–90 на пост**. Лучше больше — отбор дешевле, чем повторный поиск.
- Темы извлекать из текста поста: ключевые люди/персонажи, места, произведения-референсы, настроения, события. Обычно 3–5 тем.

## Шаблон промпта субагента

Подойдёт любой доступный веб-поиск: встроенные `WebSearch` / `WebFetch`, Exa
(`mcp__exa__web_search_exa` / `mcp__exa__web_fetch_exa`) или другой MCP-поисковик.
Инструмент в промпте укажи тот, что есть в твоей среде.

```
Ты — поисковый агент картинок для мудборда. Тема: <ТЕМА>.

Используй доступный веб-поиск (WebSearch / WebFetch или Exa).
Ищи широко: <СПИСОК ИСТОЧНИКОВ ПОД ТЕМУ>.

Запросы типа: "<3-6 примеров запросов, включая англоязычные и на языке оригинала>".

Нужно собрать 15-25 картинок: <что именно — кадры, постеры, портреты...>.
Только ПРЯМЫЕ URL файлов картинок (заканчиваются на .jpg/.png/.webp или отдают
image content-type), оригинального/большого размера, не миниатюры.
Проверь выборочно несколько URL через `curl -sI <url> | head -5` — HTTP 200 и image/*.

Верни ТОЛЬКО JSON-массив (без пояснений):
[{"src": "https://...", "label": "краткое описание по-русски",
  "source": "https://страница-где-нашёл", "orient": "landscape|portrait"}]
```

## Источники, которые реально работают

| Тип контента | Где брать прямые URL |
|---|---|
| Кадры фильмов | **film-grab.com** (`/wp-content/uploads/photo-gallery/...`), TMDB `image.tmdb.org/t/p/original/<hash>.jpg` |
| Постеры | TMDB (`/t/p/w1280/`), IMP Awards (`ftp.impawards.com`) |
| Аниме/тайтлы | официальный сайт тайтла (CMS часто отдаёт полноразмерные ключевые визуалы, напр. `cms.<site>.jp/app/uploads/...`), пресс-статьи Famitsu (`cimg.kgl-systems.io`), Anime News Network, animecorner.me (`static.animecorner.me`) |
| Манга/комиксы | fan wiki (fembotwiki и т.п.), archive.org (`archive.org/download/<item>/<file>.cbr/<путь>.jpg` — сканы внутри .cbr доступны как файлы) |
| Сравнения/эссе | фан-сайты (github.io страницы), киноэссе |
| Наводки | Reddit-треды — не как источник файлов, а как указатель на источники |

Не работают напрямую (JS-lazy-load, не тратить время): natalie.mu, aniverse-mag, слайдшоу-галереи.

## Люди на картинках: под контекст и под читателя

Конкретных героев поста по именам ищем всегда, у каждого своя тема мудборда. В кадрах-типажах («вайбкодер», «мама с телефоном») внешность подбирается под контекст и аудиторию: читатель должен узнать себя. Если аудитория и контекст локальные, большая часть людей в кадрах — похожие на читателя, остальных тоже ищем, выбирает пользователь мудборда. В международном контексте в кадре люди разных национальностей.

## Абстрактные понятия: мозговой штурм метафор

Для абстрактных понятий (продуктизация, рост любой ценой, одиночество) перед поиском нужен отдельный мозговой штурм: 5–10 разных визуальных метафор, а не первая пришедшая в голову. Лучше всего работают люди и сцены, в которых понятие видно: человек на сцене на фоне графика роста. Ещё сильнее — известная фигура с говорящей надписью: Стив Джобс на фоне слова «Revolutionary» для продуктизации. Известная всем фигура лучше малоизвестной, даже если вторая точнее по смыслу. Клипарт, стоковые иконки и голые графики по умолчанию не берём, но если их требует контекст (пост о самом графике, пародия на корпоративную презентацию), они уместны. В задании агенту метафоры перечисляй списком, а известные фигуры и их узнаваемые кадры называй прямо.

## Видео-кандидаты: искать, предлагать, резать только после «да»

Короткий фрагмент видео делает колоду живой сильнее любой картинки: герой поста сам произносит ключевую фразу, 15–20 секунд с субтитрами на одном слайде. Поэтому вместе с картинками ищем видео под тему: интервью и выступления героев, рекламу, в которой видна тема, эпизоды из фильмов и сериалов, которые точно показывают идею. Если в посте видео нет, его стоит поискать специально — самое яркое и точное. Хватает 3–6 кандидатов.

Видео не скачиваем и не режем сразу. В мудборд кандидат идёт темой «Видео-кандидаты»: карточка с кадром-превью, в подписи — что за ролик, отрезок с таймкодами начала и конца, что там говорится, на какой слайд и зачем; ссылка на ролик — в `source`. Тот же список с таймкодами — в `videos.md` рядом с колодой. Пользователю видео-кандидаты перечисляются отдельно с вопросом, какие брать.

Только после одобрения ролик скачивается (`yt-dlp`, нужный отрезок), таймкоды сверяются по субтитрам, фрагмент режется до 60 секунд (столько берёт карусель Instagram) и получает субтитры на языке поста. Раскладку видеослайда выбирают по формату и по тому, есть ли на слайде текст: на весь слайд с субтитрами поверх, в край листа, полосой во всю ширину с текстом под ней, окном в поле слайда. Шрифт и фон — как у соседних слайдов, подпись с источником, плюс постер-кадр для редактора. Длинные куски и целые сцены не берём: фрагмент — цитата с названным источником.

## Добор (вторая волна)

Если нужно больше картинок — новый заход агентов с **явным списком уже собранных URL** (короткими отличительными фрагментами: хэши, имена файлов), с инструкцией «не дублируй». После получения — отсев дублей по содержанию (тот же визуал в другом кропе/размере — дубль).

## Приёмка результата

1. Выборочно проверить URL: `curl -sI <url>` → HTTP 200 + `content-type: image/*`.
2. Отсеять дубли и миниатюры (`-768x432` и подобные суффиксы допустимы только если оригинала нет).
3. Каждой картинке проставить `section` (тема) и сложить всё в `moodboard-data.js`:

```js
window.MOODBOARD_DATA = [
  { src: "https://...", label: "описание по-русски", source: "https://...",
    orient: "landscape", section: "Название темы" },
  // ...
];
```

⚠️ В `label`/`section` не использовать одинарные кавычки без экранирования. Проверка: `node --check moodboard-data.js`.
